# Application Tracker

> _**Committed applications only.** Active and recent, with status. The per-application detail lives in `applications/per-application/{slug}.md`._

**Not-yet-committed opportunities go in `[[watchlist]]`, not here.** The tracker is the heavyweight layer — an entry here means the full machine ran (or is running): hiring-manager profile → binary evals → tailored variant → cover letter. Roles you're interested in, watching, or waiting on a trigger for belong in the watchlist until their trigger fires.

## Conventions

**Status:**
- `interested` — saved but not applied
- `prep` — preparing resume / cover letter / referral path
- `applied` — submitted
- `screen` — recruiter screen scheduled / in progress
- `loop` — onsite / virtual interview loop
- `offer` — offer received
- `closed-no` — rejected / withdrew
- `closed-silent` — no response, closed by you. A different signal from a rejection; don't count it as one.
- `closed-unsubmitted` — prepared but never submitted. Not evidence about your materials or fit, because the company never saw them. The built package stays reusable.
- `closed-yes` — accepted. Run the offer close-out in `docs/WORKFLOWS.md` § Between searches.

**Recording the outcome:**
- **Fact and inference stay separate.** "Rejected" is a fact. "Probably because of level" is your read; label it as one (`inferred:`) everywhere it appears. A plausible cause hardens into a remembered fact within a few sessions if nobody labels it.
- **No reason given → write `reason not captured`.** Don't fill the Outcome cell with the likeliest guess.

**When § Active is empty,** put this banner at the top of the file. It's what switches `CLAUDE.md` into dormant mode:

> _**Dormant.** No active applications as of YYYY-MM-DD. The database is in experience-management mode: capture new work as evidence; no search work unless you raise it._
